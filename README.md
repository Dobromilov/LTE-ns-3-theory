# ns-3 и LTE — база знаний

Статический сайт для совместного изучения ns-3. Сейчас доступны три материала: назначение ns-3, структура проекта ns-3.45 и вводный обзор модуля LTE.

## Структура

```text
docs/
  index.html                 # оболочка страницы и подключения статей
  content/
    outline.js               # разделы и порядок пунктов меню
    intro.js                 # отдельная статья
    architecture.js           # структура проекта
    lte-intro.js               # обзор модуля LTE
  assets/
    styles.css               # оформление
    content-helpers.js       # блоки кода, таблицы, схемы и ссылки на файлы
    app.js                   # навигация и интерактивные демонстрации
templates/
  chapter.js                 # образец новой статьи
CONTRIBUTING.md              # правила добавления материалов
```

Серверная часть, установка пакетов и сборка не требуются. Нет аккаунтов, персонального прогресса и браузерных заметок. Общие изменения — это коммиты в репозиторий; сайт не редактирует файлы через браузер.

## Открыть локально

Откройте `docs/index.html` в браузере. Или из корня проекта запустите:

```sh
python3 -m http.server 8000 --directory docs
```

Адрес: `http://localhost:8000`. Скрипты и стили подключены относительными путями, без CDN и внешних зависимостей.

## GitHub Pages

1. Загрузите файлы проекта в выбранный GitHub-репозиторий. Служебный каталог `.openai/` относится к Sites и для GitHub Pages не нужен.
2. В `Settings → Pages` выберите `Deploy from a branch`.
3. Укажите ветку с материалами и каталог `/docs`, сохраните настройки.
4. Добавляйте изменения в выбранную ветку; Pages будет публиковать её каталог `docs/`.

Источник: [настройка источника публикации GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).

GitHub-репозиторий этим проектом автоматически не создавался, публикация на GitHub пока не выполнялась. Копия на Sites может публиковаться независимо; редактирование GitHub не обновляет Sites автоматически.

## Совместная работа

Редактируйте нужную статью в `docs/content/`, создавайте отдельные ветки и объединяйте изменения через pull request. Отдельные файлы статей позволяют работать над разными темами без постоянных конфликтов одного большого HTML.

Как добавить материал, фрагмент кода и диаграмму: [CONTRIBUTING.md](CONTRIBUTING.md).

## Границы интерактивных примеров

Демонстрация событий иллюстрирует модельное время; карта каталогов объясняет устройство репозитория. Они не запускают ns-3 и не читают файловую систему посетителя. Технический разбор должен указывать версию исходников и условия эксперимента.

## Копия на Sites

Для упаковки Sites исходники из `docs/` копируются в игнорируемый `dist/`:

```sh
node scripts/prepare-static.mjs
```

Для GitHub Pages этот шаг не нужен: публикуется непосредственно `docs/`.
